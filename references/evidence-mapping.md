# 证据表 → 设计书 的映射

设计书里**每条依据都应能追到证据表条目**。追不到，就是悬空依据。

| 设计书章节 | 证据来源 | 注意 |
|---|---|---|
| 现有研究证据 | 证据表「关键结果」列 | **数字须回原文核过** |
| 研究空白 | 证据表 + 收口判据 | ⚠️ **≥2 条独立证据**；同源团队 / 同队列**不算独立** |
| 研究假设 | 证据表 + 收口判据 | 假设须能被证伪（D1） |
| 样本量 | 证据表「关键结果」的效应量 | ⚠️ 人群可比性（D2 规则） |
| 统计方案 | 证据表「研究设计」列 | 方法学参照 |

---

## ⚠️ 最常见的悬空：把二手陈述当一手证据

一类反复出现的问题：

| 症状 | 例 |
|---|---|
| 把**转引**当原始研究 | 「综述称 X 研究发现了 Y」→ 直接写成「X 研究发现了 Y」，没读原文 |
| 把**元分析**当原始研究 | 引用的是 meta 的合并值，却当成某一项原始研究的结果 |
| 把**反推值**当文献值 | 自己从两个数字算出来的值，写成「文献报道」 |
| 把**同源团队**当独立证据 | 同一课题组的三篇论文，当成三条独立证据支撑「研究空白」 |

**共同点：没有回到原文原句。**

---

## 对接动作

1. 从项目证据表或文献表筛选相关条目
2. 为每条补一栏「**对本课题的意义**」
3. 生成**分区证据表**（按设计书章节分组）
4. 逐条审计：设计书每一句依据 → 证据表哪一行

**审计脚本化的部分可以自动比对；语义判断（这条证据真的支持这句话吗）必须人工过。**
